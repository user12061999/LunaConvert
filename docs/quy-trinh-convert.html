Bạn có một file *_unityads.html export từ Luna Playground. Đây là quy trình biến nó thành build hợp lệ cho Mintegral, Google Ads, AppLovin, Meta và TikTok: sửa chỗ nào, thay hàm nào, và network nào không được có hàm nào.

Bước 1Bốn sửa chung cho mọi network

Làm trước, một lần, trên bản gốc. Bốn sửa này giống nhau cho cả bốn network — sau đó mới nhân bản ra từng bản riêng.

1.1 Xoá block ghi đè consolegrep: devToolsAreOpen · bắt buộc

Luna nhúng một block remote-debugging wrap cả 6 method của console:

const s = ["debug","trace","info","log","warn","error"];
for (const t of s) {
  const s = console[t];
  console[t] = (...r) => { …; window.devToolsAreOpen ? s.apply(console, r) : o++ }
}

Mintegral báo lỗi #15 Do not override global console method. Block này còn swallow log khi devtools đóng, và poll console.re mỗi 100ms vô hạn.

Cách sửa: xoá cả thẻ <script>…</script> chứa nó, không phải chỉ vòng for. Nó là IIFE độc lập. Sau khi xoá, kiểm ba symbol này phải về 0:

grep -c 'devToolsAreOpen'   build.html   # 0
grep -c 'console\.re'       build.html   # 0
grep -c 'consolerescript'   build.html   # 0
node -e 'console.log' … → console.log.toString() phải chứa "[native code]"

1.2 Sửa tag đóng ở cuối filegrep: tail -c 100 · bắt buộc cho Google

File Luna kết thúc bằng tag thừa. Browser bỏ qua nên test bằng mắt không thấy, nhưng Google validate explicit end tags sẽ bắt:

…</script></body>
</html></head></html>          ← sai
…</script></body>
</html>                          ← đúng

1.3 Dọn playgroundAssetOverridesgrep: playgroundAssetOverrides · bắt buộc

Rác của Playground preview harness — map trỏ asset ra CDN của Luna:

window.playgroundAssetOverrides = {"42706":"https://assets.lunalabs.io/…/….m4a"};
window.playgroundAssetOverrides = {};

File audio đó đã bake inline trong build rồi. Nhưng kiểm trước khi xoá: đếm số lần biến này xuất hiện — phải đúng 1 lần (tức là không code nào đọc nó). Nhiều hơn 1 thì có code đọc, phải xử lý tay:

grep -o 'playgroundAssetOverrides' build.html | wc -l   # phải = 1

1.4 De-host hai script debuggrep: mrdoob.github.io, cdn.jsdelivr.net

Hai loader này chỉ chạy khi URL có query param ?bundles / ?spector nên không bao giờ fire thật — nhưng static scanner vẫn đọc chuỗi URL, và cả hai host đều nằm ngoài whitelist của Google.

https://mrdoob.github.io/stats.js/build/stats.min.js       → about:blank
https://cdn.jsdelivr.net/npm/spectorjs@…/spector.bundle.js  → about:blank

Xong bốn bước, kiểm lại host còn sót. Chỉ được còn store link — và tpc.googlesyndication.com nếu là bản Google:

grep -oE 'https?://[a-zA-Z0-9._-]+' build.html | sort -u

Kiểm luôn store link tại đây. grep -o 'iosLink:"[^"]*"' build.html — nếu rỗng thì traffic iOS bấm CTA sẽ mở vào chuỗi trống. Không preview tool nào bắt được lỗi này vì tool chỉ báo "đã có store click", không kiểm link trỏ đi đâu.

Bước 2Cơ chế thay hàm CTA

Hai quy tắc dưới đây áp dụng cho cả bốn network. Hiểu chúng trước khi xem code từng network.

Quy tắc 1 — ghi đè bằng polling, đừng sửa chỗ Luna gán

Luna gán InstallFullGame bên trong Bridge.ready() ở event luna:build. Sửa trực tiếp code minify đó rất dễ vỡ. Thay vào đó thêm một thẻ <script> mới ngay trước </body> và ghi đè sau khi Luna khởi tạo:

var n = 0, iv = setInterval(function(){
  var P = window.Luna && Luna.Unity && Luna.Unity.Playable;
  var L = window.Luna && Luna.Unity && Luna.Unity.LifeCycle;
  if (P && P.InstallFullGame && !P.InstallFullGame.__mine) P.InstallFullGame = cta;
  if (L && !(L.GameEnded && L.GameEnded.__mine))            L.GameEnded    = ended;
  if (++n > 600) clearInterval(iv);          // bỏ cuộc sau 60s
}, 100);

Dùng polling thay vì addEventListener("luna:build") vì listener của bạn có thể chạy trước listener của Luna, rồi bị Luna ghi đè lại. Polling thì luôn thắng. Cờ __mine để không gán lại vô ích mỗi 100ms.

Helper store link dùng chung cho mọi network:

function storeUrl(){
  var c = (window.$environment && window.$environment.packageConfig) || {};
  return /iphone|ipad|ipod|macintosh/i.test(navigator.userAgent) ? c.iosLink : c.androidLink;
}

Quy tắc 2 — viết tên hàm nguyên văn

Preview tool của network quét chuỗi literal trong source, không chạy code. Viết gọn kiểu này thì code chạy đúng nhưng validator báo thiếu API:

var F = window.FbPlayableAd;
if (F && F.onCTAClick) F.onCTAClick();        // chạy đúng, validator không thấy

if (typeof FbPlayableAd !== "undefined" && FbPlayableAd.onCTAClick) {
  FbPlayableAd.onCTAClick();
}                                          // đúng

Áp dụng cho mọi API network: window.install(, window.gameEnd(, ExitApi.exit(, mraid.open(, FbPlayableAd.onCTAClick(. Đây là loại lỗi test runtime không bắt được — chỉ grep source mới thấy.

Bước 3Từng network: cần gì, không được có gì

Mỗi network chỉ khác nhau ở hàm CTA, vài hàm lifecycle, và cách đóng gói. Code dưới đây dán vào thẻ <script> mới trước </body>.

AppLovin dùng MRAID giống Unity Ads nên CTA gần như giữ nguyên. Nhưng có hai thứ phải làm thêm mà nếu bỏ qua thì không ai báo lỗi — chỉ mất tracking hoặc CTA thỉnh thoảng không ăn.

Phải có

  • Chạy được cả portrait và landscape
  • Đóng gói single HTML, không nhận ZIP

Không được có

  • window.open() hoặc clickTag trần làm CTA
  • Gọi MRAID API trước khi ready
  • Bất kỳ external network call nào
  • Auto-click, auto-play audio trước tương tác
function al(ev){                        // luôn bọc typeof — AppLovin yêu cầu
  try { if (typeof window.ALPlayableAnalytics !== "undefined" && window.ALPlayableAnalytics.trackEvent)
    window.ALPlayableAnalytics.trackEvent(ev); } catch(e){}
}

function cta(){
  al("CTA_CLICKED");
  var url = storeUrl();
  if (typeof mraid === "undefined" || !mraid.open) { window.open(url, "_blank"); return; }
  // gate: không gọi mraid khi đang loading
  if (mraid.getState && mraid.getState() === "loading") {
    mraid.addEventListener("ready", function once(){
      mraid.removeEventListener("ready", once);
      mraid.open(url);
    });
    return;
  }
  mraid.open(url);
}
cta.__mine = 1;

var endSent = false;

}

// funnel phải đúng thứ tự và không lặp
var FUNNEL = ["LOADING","LOADED","DISPLAYED"], sent = 0;
function mark(stage){
  var upto = FUNNEL.indexOf(stage) + 1;
  while (sent < upto) { al(FUNNEL[sent]); sent++; }
}
mark("LOADING");
window.addEventListener("luna:build", function(){ mark("LOADED");    });
window.addEventListener("luna:start", function(){ mark("DISPLAYED"); });

Vì sao funnel cần state machine chứ không map thẳng: Luna pipeline 3.1.0 dispatch luna:start trước luna:build. Map thẳng hai event đó thì AppLovin nhận DISPLAYED trước LOADED — funnel sai mà đọc code không thấy, chỉ lộ ra khi chạy thật.

Nếu game có gọi challenge event từ C# thì cần thêm phần này. Trong build unityads, Luna.Unity.Analytics.Applovin chỉ là object rỗng — mọi call LogChallengeStarted() rơi vào hư không:

var CHALLENGE = {
  LogChallengeStarted:"CHALLENGE_STARTED", LogChallengeFailed:"CHALLENGE_FAILED",
  LogChallengeRetry:"CHALLENGE_RETRY",     LogChallengePass25:"CHALLENGE_PASS_25",
  LogChallengePass50:"CHALLENGE_PASS_50",  LogChallengePass75:"CHALLENGE_PASS_75",
  LogChallengeSolved:"CHALLENGE_SOLVED"
};
function setFn(ns, name, ev){
  var f = function(){ al(ev); }; f.__mine = 1;
  // Bridge định nghĩa các member này là accessor không enumerable
  try { Object.defineProperty(ns, name, {value:f, writable:true, enumerable:false, configurable:true}); }
  catch(e){ try { ns[name] = f; } catch(e2){} }
}
// trong vòng poll, cùng chỗ ghi đè InstallFullGame:
var A = window.Luna && Luna.Unity && Luna.Unity.Analytics;
if (A) {
  if (!A.Applovin) A.Applovin = {};
  // kiểm hàm THỰC TẾ có phải của mình không — Bridge có thể thay cả object sau init
  if (!(A.Applovin.LogChallengeStarted && A.Applovin.LogChallengeStarted.__mine)) {
    for (var k in CHALLENGE) { setFn(A.Applovin, k, CHALLENGE[k]); setFn(A.Applovin, k+"$1", CHALLENGE[k]); }
  }
}

Hai chi tiết dễ sai ở đây: Bridge định nghĩa các member đó là accessor không enumerable (nên Object.keys không thấy, và phép gán thường có thể không ăn), và Bridge có thể thay thế cả object sau khi khởi tạo — nên phải kiểm hàm thực tế mỗi vòng poll, không đánh dấu object một lần rồi bỏ qua. Bridge sinh cả tên trần và tên có hậu tố $1, wire cả hai.

4.2 Runtime — bắt lỗi grep không thấy

Mở file trong browser với SDK giả của network, rồi kiểm hàm nào thực sự được gọi. Ví dụ cho Meta — dán vào console trước khi load file:

window.__calls = [];
window.FbPlayableAd = {
  onCTAClick:       function(){ __calls.push("onCTAClick") },
  logGameLoad:      function(){ __calls.push("logGameLoad") },
  logLevelComplete: function(n){ __calls.push("logLevelComplete:" + n) }
};
window.open = function(u){ __calls.push("WINDOW_OPEN:" + u); };   // bẫy fallback

// sau khi game load xong, bấm CTA rồi kiểm:
__calls   // phải có "onCTAClick", KHÔNG được có "WINDOW_OPEN"

Cái gì KHÔNG bị xoá — và vì sao không sao

Đây là chỗ dễ hiểu nhầm cụm "network X không được có hàm Y". Nó có nghĩa là không được phụ thuộc vào, hoặc không được để chạy — chứ không phải phải xoá khỏi file. Code MRAID gốc của Luna vẫn nằm nguyên trong cả bốn bản:

Hệ quả thực tế

Vì cả năm bản dùng chung một base đã làm sạch và chỉ khác nhau ở phần thêm vào cuối <body>, nên khi có build mới từ Luna bạn không phải làm lại từ đầu cho từng network: làm sạch một lần, rồi ghép adapter tương ứng. Đó cũng chính là cách tool tự động hoá quy trình này hoạt động.

Quy trình này áp dụng cho bản export *_unityads.html của Luna Playground, pipeline 3.1.0. Nếu Luna đổi pipeline thì các mốc grep ở bước 0 có thể lệch — định vị lại bằng chính các từ khoá đó trước khi sửa.

Cách chính thống vẫn là re-export từ Luna Playground với network tương ứng: Luna build sẵn adapter cho từng network. Nhưng chỉ Unity Ads là free, phần còn lại cần Pro plan — quy trình trên là đường đi khi bị chặn ở đó.
